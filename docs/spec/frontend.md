# Frontend User Guide

## 1. Призначення frontend
Frontend реалізований як окремий React/Vite застосунок і виконує три головні ролі:
- публічний інтерфейс каталогу;
- інтерфейс авторизації та особистого кабінету;
- адміністративно-модераційний інтерфейс.

## 2. Основні маршрути
### `/`
Головна сторінка з презентаційним позиціонуванням платформи.

### `/catalog`
Публічний каталог оголошень з:
- картками;
- фільтрами;
- пошуком;
- сортуванням;
- переходом на детальну сторінку.

### `/catalog/:id`
Детальна сторінка одного оголошення:
- основна інформація;
- галерея;
- seller info;
- повідомлення автору;
- пов’язані / схожі пропозиції.

### `/workspace`
Приватна робоча область користувача:
- логін / реєстрація;
- профіль;
- створення оголошення;
- upload зображень;
- власні оголошення;
- повідомлення;
- модерація (для moderator/admin);
- операційна панель (для admin/moderator).

### `/errors/400`, `/errors/404`, `/errors/500`
Кастомні сторінки помилок для покращеного UX.

## 3. Ролі у frontend
### Гість
- бачить каталог;
- бачить детальну сторінку;
- може перейти до входу або реєстрації.

### User
- може створювати оголошення;
- може завантажувати зображення;
- може переглядати власні оголошення;
- може писати повідомлення.

### Moderator
- бачить чергу модерації;
- може схвалювати або відхиляти оголошення.

### Admin
- має всі права модератора;
- бачить операційну панель;
- може створювати категорії та керувати користувачами через API.

## 4. Сценарій демонстрації
### Сценарій 1. Пошук у каталозі
1. Відкрити `/catalog`
2. Використати текстовий пошук
3. Застосувати фільтр за категорією
4. Відсортувати результати
5. Відкрити детальну сторінку

### Сценарій 2. Публікація оголошення
1. Увійти у `/workspace`
2. Заповнити форму створення оголошення
3. Завантажити або вказати зображення
4. Натиснути публікацію
5. Переконатися, що оголошення потрапило в статус `pending`

### Сценарій 3. Модерація
1. Увійти під `moderator` або `admin`
2. Відкрити `/workspace`
3. Переглянути блок модерації
4. Схвалити або відхилити оголошення

### Сценарій 4. Повідомлення
1. Відкрити картку оголошення
2. Надіслати повідомлення автору
3. Перевірити вхідні/вихідні повідомлення у workspace

## 5. Локальний запуск
### Варіант 1. Окремо backend + frontend
```powershell
uvicorn src.main:app --reload
cd frontend
npm install
npm run dev
```

### Варіант 2. Через Docker
```powershell
docker compose up --build
```

### Варіант 3. Локальний helper script
```powershell
.\run.ps1
```

## 6. Основні адреси
- frontend: `http://127.0.0.1:5173`
- backend API: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- MongoDB: `mongodb://localhost:27017`

## 7. UI/UX акценти
- каталог орієнтований на сценарій “знайти пропозицію швидко”;
- окремі error pages замінюють сирі технічні помилки;
- модераційний інтерфейс винесений у зрозумілий окремий блок;
- операційна панель не показується звичайному користувачу;
- візуальна мова frontend узгоджена між home, catalog і workspace.

## 8. Обмеження та очікування
- створення категорій доступне тільки `admin` або `moderator`;
- створення оголошень доступне тільки авторизованому користувачу;
- деякі дії вимагають актуального JWT;
- публікація нового оголошення не означає миттєву появу в каталозі, якщо воно ще не схвалене модерацією.
